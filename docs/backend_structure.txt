# SKILLS UP - BACKEND STRUCTURE

Bu hujjat backend dasturchi uchun yozilgan. Frontend (React + TypeScript) tayyor: hozir hamma ma'lumot brauzerda (localStorage va mock data) turibdi. Backend shu ma'lumotlarni va qoidalarni serverga ko'chiradi. Hujjatda: rollar, ma'lumotlar bazasi jadvallari, biznes qoidalari (aniq raqamlar bilan), hisoblash formulalari va API ro'yxati bor.

Bu hujjat asosida backend loyihasi yozilgan: papka backend/ (NestJS, qarang backend/README.md); frontend alohida papkada: frontend/. Hujjatdagi hamma raqam va qoida frontend kodidan olingan. Qoida o'zgarsa, frontend ham o'zgaradi, shuning uchun backendda ularni bitta joyda (konfiguratsiya) saqlang.

## 1. UMUMIY MA'LUMOT

- Tizim: o'quv markazi platformasi "Skills Up". Til: o'zbekcha (faqat logo "Skills Up" inglizcha). Xato va xabar matnlari o'zbekcha.
- Uch rol: STUDENT (o'quvchi), TEACHER (ustoz), ADMIN (administrator). Rol login va paroldan aniqlanadi.
- Pul: faqat so'm (UZS), butun son (tiyin yo'q). Masalan 500000.
- Vaqt: ISO 8601, vaqt mintaqasi Asia/Tashkent (UTC+5). Bazada UTC saqlash, javobda ISO bilan berish tavsiya etiladi.
- Dars davomiyligi: dars xonada 2 soat (jadval katagi). Dars yozuvidagi duration_min alohida (video uzunligi, 10-240 daqiqa).
- Valyuta, til va boshqa doimiy qiymatlar (XP, ball, jarima) konfiguratsiyada bo'lsin (7-bo'limga qarang).

## 2. TEXNOLOGIYA TAVSIYASI

Backend NestJS (TypeScript) da yoziladi. Hujjatning 1-14 bo'limlari framework'dan mustaqil (jadvallar, qoidalar, API), 15-bo'limda shu tuzilma NestJS modullariga, guardlariga, DTO va servislariga moslab berilgan. Frontend uchun faqat REST + JSON kerak:

- NestJS + TypeScript (frontend ham TypeScript: DTO va tur nomlarini bir xil qilsangiz ulash oson)
- REST API, JSON, prefiks: /api/v1
- Baza: PostgreSQL (jadvallar quyida); ORM: TypeORM yoki Prisma (o'zingiz tanlang)
- Fayl saqlash: S3-mos saqlash yoki server diski (jadval: files)
- Autentifikatsiya: JWT ISHLATILMAYDI. Login qilganda server tasodifiy token (sessiya) beradi va uning xeshini bazada saqlaydi (sessions jadvali, 5.1). Token har so'rovda `Authorization: Bearer <token>` bilan yuboriladi. JWT_SECRET kerak emas.
- Parol xeshi: argon2id yoki bcrypt (frontend demo uchun SHA-256 ishlatgan, buni ishlatmang)

## 3. ROLLAR VA RUXSATLAR

ROL: STUDENT
- O'z guruhlarini, darslarini, vazifalarini ko'radi.
- Dars videosini ko'radi (progress yoziladi), vazifa topshiradi (matn + fayl).
- Reyting, to'lovlar tarixi, keyingi to'lovlar, bildirishnomalar, qo'llanma/FAQ, karyera videolari.
- O'z parolini o'zgartiradi. Ism, email, telefonni o'zgartira OLMAYDI.

ROL: TEACHER
- Faqat O'Z guruhlari (groups.teacher_id = o'zi) bilan ishlaydi.
- Dars boshlaydi (imtihon qilib belgilashi mumkin), dars ma'lumotlarini (tavsif, video havola/fayl, davomiylik) kiritadi.
- Uyga vazifa beradi (matn, qadamlar, muddat, fayl), topshirilgan ishni baholaydi yoki qaytaradi.
- Davomat belgilaydi, saqlaydi (qulflaydi), qayta ochadi. Jurnalni ko'radi. Imtihon ballini kiritadi.
- O'z parolini o'zgartiradi.

ROL: ADMIN
- O'quvchi qo'shadi, guruhga joylaydi. Ustoz qo'shadi.
- O'quvchi va ustozning login va parolini o'zgartiradi.
- Xona qo'shadi, nomini va sig'imini o'zgartiradi. Xonalar jadvalini (band/bo'sh) ko'radi.
- Guruh ochadi (kunlar, 2 soatlik vaqt, xona, ustoz).
- Guruhning to'lov sanasi va summasini belgilaydi: shu guruhdagi hamma o'quvchiga bildirishnoma boradi.
- O'z parolini o'zgartiradi.

Har so'rovda server rolni va egalikni tekshirishi shart (masalan ustoz boshqa ustozning guruhiga tegolmaydi, o'quvchi boshqa o'quvchining ishini ko'rolmaydi).

## 4. AUTENTIFIKATSIYA

Login sahifasi: login + parol. Rol hisobga qarab aniqlanadi.

- POST /auth/login  { "login": "...", "password": "..." }  ->  { "token": "...", "user": { id, role, fullName } }
- Login katta-kichik harfga e'tiborsiz (saqlashda kichik harfda).
- Xato bo'lsa HAR DOIM bitta umumiy javob: 401 "Login yoki parol noto'g'ri." (qaysi biri xato ekanini aytmang).
- Urinishlarni cheklang (rate limit), ketma-ket xatolardan keyin vaqtincha bloklang.
- POST /auth/logout: sessiya serverda o'chiriladi, token darhol ishlamay qoladi (204).
- POST /auth/refresh: joriy token yangisiga almashtiriladi (yangi muddat), eskisi ishlamaydi.
- Sessiya muddati SESSION_HOURS (standart 12 soat). Muddati o'tgan, noma'lum yoki o'chirilgan token -> 401.
- Parol o'zgarganda sessiyalar tugaydi: admin boshqa odamning parolini o'zgartirsa, uning HAMMA sessiyasi o'chadi; o'zi o'zgartirsa, boshqa qurilmalardagi sessiyalar o'chadi, hozirgisi qoladi.
- Login: 4-30 belgi, faqat kichik lotin harflari, raqam, nuqta, pastki chiziq, chiziq (a-z 0-9 . _ -). Butun tizimda UNIKAL (o'quvchi, ustoz, admin orasida).
- Parol: kamida 8 belgi. O'z parolini o'zgartirishda kamida bitta harf va bitta raqam bo'lishi, eski paroldan farq qilishi kerak.
- Parolni o'zgartirish (o'zi): POST /me/password { current, next } -> joriy parol noto'g'ri bo'lsa 422 "Joriy parol noto'g'ri."
- Administrator hisobi muhit o'zgaruvchilaridan boshqariladi: ADMIN_LOGIN (standart: admin) va ADMIN_PASSWORD (kamida 8 belgi). Backend har ishga tushganda bazani shularga moslaydi: admin yo'q bo'lsa yaratadi, parol farq qilsa yangilaydi (shu adminning sessiyalari tugaydi). Parol kod ichida yozilmaydi. ADMIN_PASSWORD bo'sh bo'lsa, admin hisobiga tegilmaydi.
- Admin boshqa odamning loginini/parolini o'zgartiradi (9.4-bo'lim, ADMIN).
- Rol bo'yicha yo'naltirish va rol guard: 4.1 va 4.2 bo'limlar.
- Hech qachon parol yoki xesh javobda qaytmasin.

### 4.1 Login -> rol -> o'z sahifasi (frontend oqimi)

Frontend login sahifasidan keyin rolga qarab O'Z panelini ochadi. Backend shu oqimni ta'minlashi kerak:

```
1. Foydalanuvchi /login da login va parolni yozadi.
2. POST /auth/login  ->  { token, user:{ id, role, fullName } }
3. Frontend role ga qarab o'tadi:
      role = STUDENT  ->  /            (o'quvchi bosh sahifasi)
      role = TEACHER  ->  /teacher     (ustoz paneli)
      role = ADMIN    ->  /admin       (admin paneli)
4. Sahifa yangilanganda frontend GET /me ni chaqiradi: token yaroqli bo'lsa role va ism olinadi, aks holda 401 -> /login.
5. "Chiqish" tugmasi: POST /auth/logout (sessiya serverda o'chadi), token o'chiriladi, /login ga qaytadi.
```

Misol: login o'quvchiniki bo'lsa (masalan "bekzod.rahimov"), kirgach O'QUVCHI paneli ochiladi va unda aynan SHU o'quvchining ma'lumotlari (guruhlari, darslari, XP, vazifalari, to'lovlari) ko'rinadi. Ustoz logini bilan kirsa ustoz paneli, admin logini bilan kirsa admin paneli ochiladi. Rolni foydalanuvchi o'zi tanlamaydi: u faqat login va paroldan keladi.

NOTA: frontend hozir (mock) o'quvchi paneli uchun bitta demo o'quvchining ma'lumotini ko'rsatadi. Backend ulanganda har o'quvchi o'zinikini ko'radi.

### 4.2 Rol guard (sahifalarni rol bo'yicha himoyalash)

Frontendda marshrut himoyasi (route guard) bor va quyidagicha ishlaydi:

```
Holat                                                                 Natija
------------------------------------------------------------------------------------------------------
Tizimga kirmagan odam istalgan sahifani ochsa (/admin, /lessons...)   /login ga yo'naltiriladi
O'quvchi /admin yoki /teacher... manzilini ochsa                      o'quvchi bosh sahifasiga (/) qaytariladi
Ustoz /admin yoki o'quvchi sahifalarini (/lessons, /payments...) ochsa  ustoz bosh sahifasiga (/teacher) qaytariladi
Admin /teacher... yoki o'quvchi sahifalarini ochsa                    admin bosh sahifasiga (/admin) qaytariladi
Tizimga kirgan odam /login ni ochsa                                   o'z bosh sahifasiga o'tadi
O'z panelining ichki sahifalari                                       ochiladi
```

Rolga tegishli sahifa manzillari:

```
STUDENT   /, /lessons, /lessons/:id, /leaderboard, /career, /guides, /groups, /analytics, /payments, /settings
TEACHER   /teacher, /teacher/groups, /teacher/lessons, /teacher/lessons/new, /teacher/lessons/:id, /teacher/journal, /teacher/review, /teacher/settings
ADMIN     /admin, /admin/students, /admin/teachers, /admin/groups, /admin/rooms, /admin/payments, /admin/settings
```

MUHIM (backend uchun): frontend guard faqat sahifalarni brauzerda yashiradi, uni chetlab o'tish mumkin. HAQIQIY himoya backendda bo'lishi shart:

- Har so'rovda tokendan rol va foydalanuvchi aniqlansin. Rol endpoint prefiksiga mos kelmasa 403 qaytsin: /student/* faqat STUDENT, /teacher/* faqat TEACHER, /admin/* faqat ADMIN.
- O'quvchi endpointlarida o'quvchi identifikatori URL dan EMAS, tokendan olinsin (/student/... har doim "men"). Shunda o'quvchi boshqa o'quvchining ma'lumotini ko'ra olmaydi.
- Ustoz endpointlarida guruh/dars shu ustozniki ekani tekshirilsin (groups.teacher_id = token user), aks holda 403.
- Token yaroqsiz yoki muddati tugagan bo'lsa 401: frontend /login ga qaytaradi. 403 kelsa frontend foydalanuvchini o'z bosh sahifasiga qaytaradi.

## 6. BIZNES QOIDALARI (ANIQ RAQAMLAR)

### 6.1 Konfiguratsiya qiymatlari

```
ATTENDANCE_XP        = 20     darsga qatnashish uchun XP (hamma darsda bir xil)
ATTENDANCE_GEMS      = 10     darsga qatnashish uchun kumush
MIN_BALL / MAX_BALL  = 1 / 100   vazifa va imtihon bali (butun son)
XP_PER_BALL          = 1      1 ball = 1 XP
BALL_PER_GEM         = 2      har 2 ball = 1 kumush (yaxlitlash: Math.round(ball / 2))
LATE_PENALTY         = 10     kechikib topshirilsa, balldan ayiriladigan ball
XP_PER_LEVEL         = 250    bosqich (level) uchun XP
HOMEWORK_LIMITS      = 1, 3, 24, 72, 168 soat   (1 soat, 3 soat, 1 kun, 3 kun, 1 hafta)
RETURN_EXTENSION_H   = 24     qaytarilgan ishga beriladigan yangi muddat (soat)
LESSON_SLOTS         = 08:00, 10:00, 12:00, 14:00, 16:00, 18:00, 20:00 (har biri 2 soat)
DEFAULT_ONLINE_CAPACITY = 15
```

### 6.2 Dars va video progress

- O'quvchi videoni ko'radi. Progress = videoning ENG ILGARI ko'rilgan joyi (foizda). Oldinga o'tkazib yuborish bilan progress oshmaydi, faqat o'ynatib ko'rish bilan oshadi (frontend buni ta'minlaydi, backend faqat oshishga ruxsat bersin: yangi qiymat >= eskisi).
- Progress 100 bo'lsa, dars "tugatilgan" (completed), aks holda "jarayonda" (in-progress). Birinchi ko'rishdan 100% gacha davom ettirish mumkin (qaldirgan joyidan).
- DARSLARGA KIRISH CHEKLANMAGAN: oldingi darsning vazifasi topshirilmagan bo'lsa ham o'quvchi keyingi darsni ochadi va qatnashadi. Vazifa faqat IMTIHONga kirishga ta'sir qiladi (6.6).
- Karyera videolari: faqat ko'rish, progress yozilmaydi.

### 6.3 Davomat

- Ustoz har o'quvchini "qatnashdi" yoki "qatnashmadi" deb belgilaydi (dars boshlangan bo'lsa; rejalashtirilgan darsga davomat qo'yib bo'lmaydi).
- Ustoz belgisi YO'Q bo'lsa: video progress 100 bo'lsa qatnashgan hisoblanadi.
- Ustoz belgisi BOR bo'lsa: shu belgi ustun (video ko'rilgan-ko'rilmaganiga qaramay).
- "Hammasi qatnashdi" tugmasi: hali qatnashmagan hammani present = true qiladi.
- "Davomatni saqlash": lessons.attendance_saved = true. Shu paytda hisoblangan natija HAR BIR o'quvchi uchun attendance jadvaliga aniq (explicit) yozilsin (video asosida hisoblanganlar ham). Saqlangandan keyin davomatni tahrirlash endpointlari 409 qaytaradi ("Davomat saqlangan").
- "Davomatni tahrirlash": attendance_saved = false (faqat ustoz). Jurnalda saqlangan darslar qulf belgisi bilan ko'rinadi, katak o'zgarmaydi.
- Qatnashish uchun mukofot: har doim ATTENDANCE_XP va ATTENDANCE_GEMS.

### 6.4 Uyga vazifa

Berish (ustoz):
- Matn: kamida 10 belgi. Qadamlar: kamida 1 ta (har biri alohida qator, bo'sh emas).
- Muddat: HOMEWORK_LIMITS dan biri; due_at = hozirgi vaqt + muddat; assigned_at = hozir.
- Fayl: ixtiyoriy, 5 tagacha, har biri 20 MB gacha (8-bo'lim).
- Vazifa berilganda shu guruhning hamma o'quvchisi uchun student_homework NOT_DONE bo'lib yaratiladi.
- Vazifani YANGILASH (matn, qadam, muddat, fayl) faqat hali topshirmaganlarga ta'sir qiladi: ya'ni holati "berilmagan" yoki NOT_DONE bo'lganlarga. Topshirgan (PENDING), qaytarilgan (RETURNED) yoki baholangan (DONE) o'quvchilar o'z holati va muddatini saqlab qoladi.
- Dars boshlangandan KEYIN guruhga qo'shilgan o'quvchi uchun ham student_homework yaratilsin.

Holatlar (o'quvchi uchun) va o'tishlar:

```
berilmagan (qator yo'q)  --ustoz vazifa beradi-->  NOT_DONE
NOT_DONE   --o'quvchi topshiradi-->               PENDING
PENDING    --ustoz baholaydi (ball 1..100)-->     DONE
PENDING    --ustoz qaytaradi (izoh bilan)-->      RETURNED   (assigned_at = hozir, due_at = hozir + 24 soat, grade o'chiriladi)
RETURNED   --o'quvchi qayta topshiradi-->         PENDING
DONE       --ustoz bahoni o'zgartiradi-->         DONE (yangi ball) yoki RETURNED
```

Frontendda holat nomlari: Bajarilgan (DONE), Kutilmoqda (PENDING), Qaytarilgan (RETURNED), Bajarilmagan (NOT_DONE), Berilmagan.

Topshirish (o'quvchi):
- Faqat NOT_DONE yoki RETURNED holatda. Muddat o'tgan bo'lsa ham topshirish MUMKIN, lekin kechikkan hisoblanadi.
- Matn (<= 2000 belgi) VA/YOKI fayl: kamida bittasi bo'lishi shart ("Javob yozing yoki kamida bitta fayl biriktiring.").
- Fayl: 3 tagacha, har biri 5 MB gacha (8-bo'lim). Papka qabul qilinmaydi.
- is_late = (topshirish vaqti > student_homework.due_at).
- Topshirgach holat PENDING.

Baholash (ustoz): ball butun son, 1..100. Ustoz ball qo'yadi (grade), holat DONE. Qaytarish: izoh (feedback) majburiy.

### 6.5 Kechikish jarimasi

- Ustoz qo'ygan ball (raw_ball) o'zgarmaydi, bazada shunday saqlanadi.
- Hisoblashda: agar ish kechikib topshirilgan bo'lsa (oxirgi topshirish is_late = true), hisobga olinadigan ball = max(1, raw_ball - 10).
- XP va kumush shu hisobga olinadigan balldan hisoblanadi.
- Interfeysda ikkala qiymat ko'rsatiladi: "85 - 10 = 75".

### 6.6 Imtihon

- Imtihon = ustoz darsni boshlayotganda "Bu dars imtihon" ni yoqqan dars (lessons.is_exam = true). 13 darsdan keyin degan qat'iy qoida YO'Q: ustoz xohlagan paytda belgilaydi.
- Imtihon guruh ichida sana bo'yicha tartiblanadi (1-imtihon, 2-imtihon...).
- Imtihon qamrab oladigan darslar: shu guruhning oldingi imtihondan (yoki guruh boshidan) beri o'tilgan oddiy (is_exam = false) darslari.
- Imtihonga KIRISH SHARTI: qamrab olingan darslarning vazifasi topshirilgan bo'lishi kerak. Kamchilik (missing) deb quyidagilar hisoblanadi: shu o'quvchi uchun vazifa berilgan, holati NOT_DONE VA muddati (due_at) o'tib ketgan. Muddati hali o'tmagan NOT_DONE vazifa kamchilik emas.
- Ruxsat bor o'quvchiga ustoz ball (1..100) kiritadi. Ruxsati yo'q o'quvchiga ball kiritish MUMKIN EMAS (backend 409 qaytarsin).
- Imtihon bali ham XP va kumushga shu qoidada aylanadi (1 ball = 1 XP, 2 ball = 1 kumush). Imtihon uchun kechikish jarimasi yo'q.
- Imtihon darsining o'zida davomat ham bor (oddiy dars kabi).
- API javobida har o'quvchi uchun imtihon holati: "done" (ball bor), "ready" (ruxsat bor, ball yo'q), "blocked" (ruxsat yo'q + missing darslar ro'yxati).

### 6.7 Guruh, xona va jadval qoidalari (admin)

- Dars vaqtlari 2 soatlik katak: 08:00, 10:00, 12:00, 14:00, 16:00, 18:00, 20:00 (tugashi +2 soat).
- Xona bandligi: (xona, hafta kuni, boshlanish vaqti) bo'yicha UNIKAL. Bir xonada bir vaqtda ikkita guruh bo'lolmaydi.
- Yangi guruh ochish: kamida 1 kun, bitta 2 soatlik vaqt, xona. Tanlangan xona BARCHA tanlangan kunlarda shu vaqtda bo'sh bo'lishi kerak.
- Ustoz to'qnashuvi: ustoz shu kun va shu boshlanish vaqtida boshqa guruhda dars o'tmasligi kerak. Xato xabari: "Ustoz shu vaqtda “<guruh>” guruhida dars o'tadi."
- Xona band bo'lsa xato: "<xona> <kun> kuni <vaqt> da band: <guruh>."
- Onlayn mashg'ulot xona band qilmaydi (room_id NULL).
- Xonani qo'shish: nom unikal (katta-kichik harfga e'tiborsiz), sig'im 1..60. Xona nomini o'zgartirsa, guruh jadvalida yangi nom ko'rinadi (jadval room_id orqali bog'langan).
- Yangi guruh ochilganda: group_schedule qatorlari (har kun uchun) + payment_plans qatori (summa >= 10000, birinchi to'lov sanasi bugundan oldin bo'lmasin).
- O'quvchini guruhga qo'shish: sig'im to'lmagan bo'lishi, o'quvchi bu guruhda allaqachon bo'lmasligi kerak. Xato: "<guruh> guruhida bo'sh joy qolmagan." / "O'quvchi bu guruhda allaqachon bor."

### 6.8 To'lov eslatmasi (admin -> o'quvchilar)

- Admin guruh uchun keyingi to'lov summasi va sanasini belgilaydi va "Saqlash va yuborish" bosadi.
- Server: payment_plans yangilanadi, payment_notices ga qator qo'shiladi, guruhning HAR BIR hozirgi o'quvchisi uchun notifications qatori yaratiladi (type = 'payment_notice').
- Bildirishnoma matni: "To'lov eslatmasi: keyingi to'lov 20-dekabr gacha, 500 000 so'm".
- Guruhda o'quvchi bo'lmasa: xato "Guruhda o'quvchi yo'q: avval o'quvchi qo'shing."
- O'quvchining "To'lovlarim" sahifasi: o'z guruhlarining payment_plans qatorlari "Keyingi to'lovlar" sifatida (guruh nomi, sana, necha kun qoldi, summa) + o'tgan to'lovlar tarixi.

## 7. HISOBLASH FORMULALARI (SERVER HISOBLASIN)

XP, kumush, bosqich, reyting bazada saqlanmaydi, qatnashish va ball ma'lumotidan hisoblanadi (yoki keshlanadi). Frontend ularni mana shunday hisoblaydi.

### 7.1 Bitta dars uchun o'quvchi mukofoti

```
attended      = ustoz belgisi bor ? present : (lesson_progress.percent == 100)
attendanceXp  = attended ? 20 : 0
attendanceGem = attended ? 10 : 0
raw_ball      = student_homework.status == 'DONE' ? grade : null
ball          = raw_ball == null ? null : (is_late ? max(1, raw_ball - 10) : raw_ball)
ballXp        = ball * 1
ballGems      = round(ball / 2)
lessonXp      = attendanceXp + ballXp
lessonGems    = attendanceGem + ballGems
```

### 7.2 Imtihon mukofoti

```
examXp   = ball * 1
examGems = round(ball / 2)
```

### 7.3 Jami XP va bosqich

```
totalXp   = sum(lessonXp over all lessons) + sum(examXp)    (o'quvchi barcha guruhlari bo'yicha)
level     = floor(totalXp / 250) + 1
levelFrom = (level - 1) * 250
levelTo   = level * 250
percent   = round((totalXp - levelFrom) / 250 * 100)
remaining = levelTo - totalXp
```

### 7.4 Guruh reytingi

- Har guruh uchun alohida reyting. O'quvchining XP si SHU guruh darslari va shu guruh imtihonlaridan yig'iladi (boshqa guruhdagi XP kirmaydi).
- Tartib: XP kamayish bo'yicha. Teng bo'lsa barqaror tartib (masalan ism bo'yicha). rank = 1,2,3...
- delta: o'tgan haftaga nisbatan o'rin o'zgarishi (+ ko'tarilgan, - tushgan). Buning uchun haftalik snapshot (jadval rank_snapshots: group_id, student_id, week, rank) kerak yoki delta ni hozircha 0 qaytaring.
- Umumiy reyting (bosh sahifa): hamma o'quvchilar orasida totalXp bo'yicha o'rin va jami o'quvchilar soni.

### 7.5 Imtihon qamrovi va ruxsat (algoritm)

```
guruh darslarini sana (va vaqt) bo'yicha tartibla
block = []
har dars uchun:
   agar dars.is_exam:  imtihon = { id = dars.id, number = (nechanchi), lessons = block }; block = []
   aks holda:          block.push(dars.id)

o'quvchi uchun imtihonga ruxsat:
   missing = imtihon.lessons ichida shunday darslar: vazifa berilgan VA student_homework.status == NOT_DONE VA due_at < hozir
   ruxsat = (missing bo'sh)
```

"Oxirgi imtihondan beri o'tilgan darslar soni" = oxirgi imtihon darsidan keyingi darslar soni (ustoz va o'quvchi interfeysida ko'rsatiladi).

### 7.6 Ustoz statistikasi (guruh bo'yicha, har o'quvchi)

Qaytariladi: rank, xp, gems, avgBall (baholangan ishlarning o'rtacha bali, yo'q bo'lsa null), held (o'tilgan darslar soni), attended (qatnashgan), assigned (berilgan vazifa), done (baholangan), pending (tekshirishni kutayotgan).

### 7.7 Jurnal (davomat jadvali)

Guruh bo'yicha: o'quvchilar x darslar. Har katak: "present", "absent" yoki "upcoming" (dars hali o'tilmagan). Har is_exam darsdan keyin imtihon ustuni (done/ready/blocked + ball). Har o'quvchi uchun: o'tilgan darslar soni, qatnashgan soni, foiz = round(attended / held * 100). Har dars uchun attendance_saved bayrog'i (qulf belgisi). Saqlangan dars katagi o'zgartirilmaydi.

### 7.8 O'quvchi bosh sahifa va tahlil

- Bosh sahifa: totalXp, gems, level (7.3), kunlik seriya (streak), guruhdagi o'rin(lar), oxirgi faoliyat (activities), yaqin hodisalar (darslar, imtihonlar, vazifa muddatlari).
- Kunlik seriya (streak): ketma-ket nechta kun o'quvchi faol bo'lgan (video ko'rgan, vazifa topshirgan yoki darsga qatnashgan). Bugun faol bo'lmasa seriya 0 ga tushadi (yoki kechagi kungacha hisoblanadi, backend qoidasini belgilasin).
- Tahlil (analytics): weeklyHours (haftalik o'qish soatlari), xpByWeek (haftalik XP), skills (ko'nikmalar foizi), completionRate (tugatilgan darslar foizi), totalHours, lessonsCompleted, avgScore (o'rtacha ball). Hammasi darslar/progress/ball dan hisoblanadi; ko'nikmalar (skills) uchun darsga teg (topic) kerak bo'lishi mumkin: ochiq savol (13-bo'lim).

### 15.2 Guard va dekoratorlar (rol guard)

```
@Controller('admin')
@UseGuards(SessionAuthGuard, RolesGuard)
@Roles(Role.ADMIN)
export class AdminStudentsController { ... }

@Controller('teacher')
@UseGuards(SessionAuthGuard, RolesGuard)
@Roles(Role.TEACHER)
export class TeacherLessonsController {
  // ustozning o'z guruhi ekanini servisda tekshiring: group.teacherId === user.id, aks holda ForbiddenException
}

@Controller('student')
@UseGuards(SessionAuthGuard, RolesGuard)
@Roles(Role.STUDENT)
export class StudentLessonsController {
  // o'quvchi id sini HECH QACHON URL/body dan olmang: @CurrentUser() user.id
}
```

- SessionAuthGuard: tokenni sessions jadvalidan tekshiradi (xesh bo'yicha), req.user = { id, role, sessionId }. Yaroqsiz yoki muddati o'tgan bo'lsa 401.
- RolesGuard: Reflector orqali @Roles ni o'qiydi, req.user.role mos kelmasa 403 (4.2-bo'lim).
- Login endpointi @Public() bilan belgilanadi (global SessionAuthGuard bo'lsa).
- Egalik tekshiruvi (ustoz-guruh, o'quvchi-o'z ma'lumoti) servis qatlamida bajariladi.

### 15.3 DTO va validatsiya (class-validator)

Har so'rov uchun DTO. Qoidalar 10-bo'limdagi jadval bilan bir xil:

```
LoginDto            @IsString() login; @IsString() password
CreateStudentDto    @Matches(/^\S+\s+\S+/) fullName; @Matches(/^\+998[ -]?\d{2}[ -]?\d{3}[ -]?\d{2}[ -]?\d{2}$/) phone;
                    @Matches(/^[a-z0-9._-]{4,30}$/) login; @MinLength(8) password; @IsArray() @IsOptional() groupIds
CreateRoomDto       @MinLength(2) name; @IsInt() @Min(1) @Max(60) capacity
CreateGroupDto      @MinLength(3) name; @MinLength(3) course; teacherId; @ArrayMinSize(1) @IsEnum(Day, {each:true}) days;
                    @IsIn(['08:00','10:00','12:00','14:00','16:00','18:00','20:00']) start; roomId;
                    @IsInt() @Min(10000) amount; @IsDateString() dueDate (bugundan oldin emas: custom validator)
StartLessonDto      groupId; @MinLength(3) title; @IsBoolean() @IsOptional() isExam
UpdateLessonInfoDto @IsOptional() description (bo'sh yoki >= 10); @Matches(/^https?:\/\/\S+$/) videoUrl; videoFileId; @IsInt() @Min(10) @Max(240) durationMin
AssignHomeworkDto   @MinLength(10) task; @ArrayMinSize(1) steps; @IsIn([1,3,24,72,168]) limitHours; @ArrayMaxSize(5) attachmentIds
SubmitHomeworkDto   @MaxLength(2000) text; @ArrayMaxSize(3) fileIds   (text yoki fayl: kamida bittasi: servisda tekshiring)
GradeDto            @IsInt() @Min(1) @Max(100) ball
ReturnDto           @IsString() @MinLength(1) feedback
PaymentPlanDto      @IsInt() @Min(10000) amount; @IsDateString() dueDate
```

Global: app.useGlobalPipes(new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })). Xatolar HttpExceptionFilter orqali 10-bo'limdagi formatga o'tkaziladi ({ error: { code, message, fields } }).

### 15.4 Entity lar (TypeORM nomlari, 5-bo'limdagi jadvallar bilan 1:1)

User, Student, Teacher, Room, Group, GroupSchedule, GroupMember, Lesson, LessonProgress, Attendance, Homework, HomeworkAttachment, StudentHomework, Submission, SubmissionFile, ExamResult, Payment, PaymentPlan, PaymentNotice, Notification, UserSettings, StoredFile (files jadvali), CareerVideo, Guide, Faq, Activity.

Muhim cheklovlar entity/migratsiyada:
- User.login unique (kichik harfga keltirib saqlang).
- GroupSchedule: unique (roomId, day, startTime) (roomId null bo'lganda cheklov yo'q).
- Homework.lessonId unique; StudentHomework PK (homeworkId, studentId).
- LessonProgress.percent faqat oshadi: servisda Math.max(eski, yangi).
- Parol xeshi @Column({ select: false }) bo'lsin: tasodifan javobga chiqib ketmasin.

### 15.6 Boshqa NestJS tavsiyalari

- Konfiguratsiya: @nestjs/config; konstantalar (ATTENDANCE_XP, LATE_PENALTY va h.k.) bitta config faylida (6.1-bo'lim).

- Migratsiyalar va seed: demo ma'lumot (12-bo'lim) faqat development muhitida.
- Testlar: RewardsService va ExamsService uchun unit testlar (formulalar 7-bo'limdagi misollar bilan).
